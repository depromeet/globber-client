# Codex 작업 순서와 최신 검증 검사

사용자 지시의 선행 조건·대상·방식·순서를 지키고, 최신 변경의 검증이 끝나기 전에 다른 작업으로 전환하지 않는다. 삭제·보존·리뷰에 한정하지 않는다. 진단·수정·재검증·질문 응답은 계속 허용한다.

## 기계적 검사

- Git이 추적하거나 무시하지 않는 파일의 경로·모드·내용으로 입력 지문을 만든다. 산출물인 `artifacts/`는 지문에서 제외한다. Git 환경변수는 제거해 부모 저장소를 오인하지 않는다.
- 하네스 변경은 하네스 전체 테스트, 제품 변경(`apps/`·`packages/` 포함)은 strict lint(`.harness/checks.json`의 `pnpm check`)·타입·전체 테스트가 필요하다. TSX/E2E 변경의 E2E 결과는 `package.json`에 `test:e2e` 스크립트가 있을 때만 요구한다. 매니페스트 파싱 오류가 필수 검사를 해제하지 않는다.
- 실제 호출 식별자·구조화된 종료 코드 0·동일한 전후 입력 지문이 일치할 때만 통과 근거를 저장한다. 실행 시작, 터미널 세션 발급, 출력 본문의 성공 문구는 통과가 아니다.
- 재검증을 시작하면 이전 통과를 해제한다. 가장 최근에 시작한 검사의 결과만 저장하며, 입력 파일이 바뀌면 이전 통과를 사용할 수 없다.
- 커밋 시에는 명령이 지정한 저장소의 인덱스로 필요한 검사를 결정한다. 스테이징과 추적 파일의 작업 트리가 다르면 커밋 전에 일치시켜 검증해야 한다. 테스트는 작업 트리에서 실행되므로 부분 스테이징 상태의 검사 결과를 커밋 인증으로 사용하지 않는다.
- 필수 검증이 남으면 새 위임·다음 작업 재개·커밋·병합·push·배포 전환을 차단한다. 일반 조회 명령의 허용 목록은 만들지 않는다.

터미널 폴링 등의 종료 정보를 런타임이 구조화해 전달하지 못하면 같은 검사기의 검증 실행 기능을 쓴다. 세션은 `CODEX_THREAD_ID`를 사용한다. 별도 스크립트나 성공 표시 파일을 수동 작성하지 않는다.

```sh
python3 .codex/hooks/workflow-gate.py verify -- node --test .harness/*.test.mjs
python3 .codex/hooks/workflow-gate.py verify -- pnpm check
python3 .codex/hooks/workflow-gate.py verify -- pnpm typecheck
python3 .codex/hooks/workflow-gate.py verify -- pnpm test
```

실행기는 실제 명령 종료를 기다리고 전후 지문을 비교하며, 명령 실패나 실행 설정 오류를 비정상 종료로 반환한다. 테스트 정의와 프로젝트 스크립트의 품질 자체를 증명하는 기능은 아니다.

## 의미 판정

- `UserPromptSubmit` 이후의 사용자 작업 지시를 세션 상태에 보관한다. 과거 transcript를 자동 수집하지 않는다. 질문 응답에서는 `answer`만 읽고 자동 훅·작업자 보고는 승인으로 취급하지 않는다.
- 사용자 지시의 선행 조건 위반, 승인 없는 대상·방식·순서 변경, 추정을 검증·승인·완료 근거로 쓰는지를 `codex exec`로 판정한다. 현재 작업의 진단·수정·검증과 명시된 가설·제안은 허용한다.
- 사용자가 승인한 전달 범위는 이 훅 적용 이후 사용자 작업 지시, 작업 종류·대상 경로, 검증 상태, 완료 보고 문장이다. 셸 명령 원문·검증 출력·협업 메시지의 불투명 값·과거 transcript는 전달하지 않는다.
- 판정기는 프로젝트 밖 임시 디렉터리에서 hooks를 끄고 read-only로 실행한다. 프로젝트 문서를 자동 로드하지 않으며 파일 읽기나 명령 실행을 하지 않도록 지시한다. 실패·시간 초과·해석 불가는 의미 판정 미확인으로 표시하고 진단을 막지 않는다. 파일 상태와 실제 검증 근거에 대한 기계적 검사는 유지한다.
- 자연어 의미를 완벽하게 판정하거나 임의 셸·MCP 동작을 격리하는 보안 경계는 아니다. 불명확한 의미를 검증 통과로 기록하지 않는다.

## 기록과 운영

- 상태는 root·session별 임시 디렉터리에 파일 잠금으로 보관한다. 별도 체크아웃·세션의 근거를 섞지 않는다.
- 새 사용자 지시는 누적하고 실제 사용자 승인과 함께 해석한다. 단순 질문만으로 앞선 실행 지시를 취소하지 않는다.
- `Stop`은 미완료를 밝힌 부분 보고와 제안을 허용하고, 근거 없는 완료·검증 주장과 지시 위반을 검사한다.
- 등록 변경과 실행 파일 변경은 별개다. 실제 세션 호출 반영을 확인하며, 삭제 대상 대신 임시 호환 파일을 임의로 남기지 않는다.
- 회귀 테스트는 실제 검사기를 실행하며 의미 판정 stub 테스트와 실제 모델·런타임 검증 결과는 구분해 보고한다.
