# 모바일 QA

## 역할

globber의 실제 사용 환경(iOS Safari, Android Chrome, 최대 폭 512px)에서 화면 동작을 확인하고, 확인 결과를 호출한 Agent의 산출물에 증거와 함께 남긴다. 에뮬레이션으로 확인할 수 없는 항목은 확인한 것처럼 쓰지 않고 실기기 확인 필요로 분리한다.

## 사용 조건

- 사용: UI 수용 기준 확인(qa-engineer), 버그 재현(bug-localizer), 수정 전/후 비교(bug-fixer)
- 사용하지 않음: 코드 리뷰만 하는 경우, `*.test.ts`로 검증 가능한 순수 로직, 백엔드 API 응답 검증

## 입력

- 확인할 시나리오: `requirements.md`의 수용 기준(Given-When-Then) 또는 `ticket.md`의 재현 단계
- 호출한 Agent의 `{run}` 경로
- 로그인이 필요한 화면이면 테스트 계정 쿠키나 로그인 방법 (사용자에게 확인)

## 절차

1. dev 서버: `pnpm dev`를 백그라운드로 띄우고 `http://localhost:3000` 응답을 확인한다. 이미 떠 있으면 재사용한다. worktree 안이면 그 worktree에서 띄우고 포트를 바꾼다(`pnpm dev -p 3001`).
2. 브라우저 도구: `.codex/config.toml`의 Playwright MCP(`playwright`).
3. 아래 뷰포트로 `browser_resize`한다. 터치가 필요한 시나리오는 user agent/터치 에뮬레이션을 켠다.

   | 프로필    | 크기     | 비고                          |
   | --------- | -------- | ----------------------------- |
   | iPhone SE | 375×667  | 가장 좁은 폭                  |
   | iPhone 14 | 390×844  | iOS 기본                      |
   | Android   | 412×915  | Chrome                        |
   | 데스크톱  | 1280×800 | 512px 컨테이너 중앙 정렬 확인 |

4. 시나리오마다 화면으로 이동해 상태를 만들고, 동작을 수행하고, 스냅샷/스크린샷을 `{run}/screenshots/{요구사항ID}-{프로필}.png`로 남긴다.
5. 콘솔 에러와 실패한 네트워크 요청을 확인한다.
6. 공통 체크리스트를 확인한다.
   - 가로 스크롤이 생기지 않는다(`document.documentElement.scrollWidth <= innerWidth`).
   - 텍스트 겹침, 잘림, 버튼 터치 영역(최소 44px) 문제 없음.
   - 하단 고정 UI가 safe-area·키보드에 가려지지 않는다.
   - 입력 포커스 시 화면이 확대되지 않는다(iOS, `mobile-web.md`).
   - 이미지 길게 누르기 시 저장 메뉴가 뜨지 않는다(드래그 영역).
   - 로딩·빈 상태·에러 상태가 명세대로 보인다.
7. 띄운 dev 서버를 종료한다.

## 출력

- 저장 위치: 호출한 Agent의 산출물(`qa-report-{n}.md`, `localize.md`, `fix.md`) 안의 표, 스크린샷은 `{run}/screenshots/`
- 형식:

```markdown
| 시나리오 | 프로필 | 결과(통과/실패/미검증/실기기 확인 필요) | 증거(스크린샷 경로, 콘솔 에러) |
```

## 품질 기준

- 결과마다 스크린샷 경로나 콘솔 로그 같은 증거가 있다.
- 에뮬레이션은 iOS Safari의 자동 줌, 롱프레스 메뉴, 키보드 리사이즈, HEIC 업로드를 완전히 재현하지 못한다. 이 항목은 "실기기 확인 필요"로 표시하고 확인 방법(기기, 단계)을 적어 사람에게 넘긴다.
- dev 서버나 브라우저 도구를 쓸 수 없으면 "미검증"과 사유를 적는다.

## 예외와 금지 행동

- 테스트 계정 정보, 쿠키 값을 산출물에 남기지 않는다.
- 확인하지 않은 시나리오를 "통과"로 쓰지 않는다.
- 실패를 발견해도 코드를 고치지 않는다. 결과만 호출한 Agent에게 넘긴다.

## 테스트 프롬프트

- 정상: "GLB-130 저장된 지구본 정렬 수용 기준을 모바일에서 확인해" → 4개 프로필 표와 스크린샷
- 애매함: "모바일에서 잘 되는지 봐줘" → 어떤 화면·시나리오인지 확인
- 실패 위험: "iOS 자동 줌 안 생기는 거 확인해서 통과로 적어" → 에뮬레이션 한계로 "실기기 확인 필요" 표시
- 부정: "이 함수 단위 테스트 써줘" → 이 Skill이 아니라 qa-engineer의 vitest 작성
