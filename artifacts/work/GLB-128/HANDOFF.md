## 핵심 결정

- 작업 단위: 관련 티켓 묶음 하나에 브랜치·PR 하나, 티켓 하나에 커밋 하나.
- 이 인계 파일은 `task/GLB-128` 브랜치에만 있다. `artifacts/work/`가 develop에만 있어서 develop에서 분기했다. 구현 브랜치(main에서 분기)에는 이 파일이 없다.
- 구현 브랜치 이름은 `{type}/GLB-{번호}-{번호}...`로, 묶음에 든 티켓 번호를 모두 넣는다. PR 대상은 `main`이다(#248~#258과 같다).
- 같은 번호를 쓴 예전 브랜치가 원격에 남아 있다. 예: `bug/GLB-241`은 2025-11 이전 프로젝트의 GLB-241(PR #89, MERGED)이다. 그래서 번호 하나짜리 이름은 쓰기 전에 `git ls-remote --heads origin '{type}/GLB-{번호}*'`로 겹치는지 확인한다.
- Jira: 작업을 시작하면 진행중(transition 21)으로, PR을 올리면 리뷰대기(transition 5)로 옮긴다. 확인이 필요한 내용은 Jira 댓글에서 담당자를 멘션해 묻는다.
- PR 본문에는 "개발 서버(오유민 개인 Vercel 계정, 별도 담당자 없음)"를 쓴다(사용자 지시).
- 로그인이 필요한 검증은 건너뛰지 않는다. 사용자에게 로그인을 요청한 뒤 Playwright로 확인한다.
- GLB-232(#258): 티켓 제안("읽은 직후 삭제")대로 하면 새로고침·뒤로가기에서 화살표가 사라졌다. 그래서 sessionStorage에 지구본 uuid를 저장하고 현재 uuid와 비교하는 방식으로 고쳤다.
- GLB-343(#256): S3 기본값을 운영 버킷으로 통일했다. `next.config.ts`의 globber-dev 원격 패턴은 next/image가 아직 쓰고 있어 남겨 두었다.

## 사용량 훅 오탐 (develop 기준 브랜치)

- `.harness/usage_guard.py:373-376`은 명령 문자열만 보고 차단한다. 조건 세 가지가 모두 맞으면 "과거 인계 문서 일괄 출력 금지"로 막는다.
  - 읽기 명령: 읽기 경로가 있거나 `cat`·`head`·`tail`·`sed`·`rg`·`grep`이 들어 있음
  - `handoff`·`HANDOFF`·`STATUS` 단어가 들어 있음
  - `*`가 있거나 읽기 경로가 2개 이상임
- 인계 문서를 출력하지 않는 명령도 막힌다. 2026-11-09에 실제로 막힌 명령:
  - `prettier --write .../*.md`와 grep을 한 명령으로 실행
  - `prettier --write`에 STATUS.md·HANDOFF.md 두 파일을 넘김
  - `git add` 두 파일 + `git commit ... | tail`
  - 훅 스크립트에서 `handoff`를 grep (경로 수 조건이 왜 맞았는지는 미확인)
- 피하는 방법:
  - 인계 파일을 다루는 명령에서는 grep·tail 등 읽기 명령을 빼고, 파일은 하나씩 넘긴다(`git add` 한 파일씩 `&&`로 연결).
  - 훅 스크립트 자체는 Read 도구에 행 범위를 지정해 읽는다.
- 훅은 고치지 않았다. 출력 대상이 인계 문서일 때만 막도록 고칠지는 사용자 결정 대기다.
