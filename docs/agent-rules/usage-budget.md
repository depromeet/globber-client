# 사용량 운영 기억

에이전트 위임·문서 탐색·검증 전에 적용한다. Claude·Codex의 영구 프로젝트 기억이며, 개인 홈 메모리나 서버 사용량 정산 자료를 뜻하지 않는다.

## 행동 규칙

1. Codex는 `fork_turns: "none"`을 명시하고 필요한 결정·경로·담당 범위만 전달한다. 위임문은 6,000자 이내로 쓴다. 작은 작업을 이유 없이 여러 에이전트로 나누지 않는다.
2. Codex 메인은 위임 중 담당 경로를 다시 읽거나 검증하지 않는다. 반환 후 검토에 집중한다. 추가 지시는 발견·결정이 생겼을 때 모아 보낸다.
3. 두 도구 모두 필요한 파일·범위만 읽는다. 과거 인계 문서 일괄 출력, 변경 없는 동일 범위 재열람을 피한다. 큰 출력은 파일·행 범위를 줄인다. 필수 규칙의 최초 읽기를 생략하지 않는다.
4. Codex 검증은 필요한 완료 후·병합 후 시점에 모은다. 성공한 검사는 파일 상태가 같으면 반복하지 않는다. 실패·변경·병합 후에는 다시 검증할 수 있다. QA 등 추가 에이전트는 실행 전에 이유·범위·검증 시점을 보고한다. 보고를 사용자 승인으로 간주하지 않는다.

## 훅 제거

Claude·Codex의 사용량 가드 훅 등록과 `.harness/usage_guard.py` 실행 코드를 제거했다. 위 행동 규칙은 문서 지침으로 유지한다. `USAGE_PLAN` 표식과 `사용량 검증 단계` 보고 형식은 더 이상 요구하지 않는다. 과거 구현·검증 내용은 Git 이력으로 확인한다.

## Codex 위임 중 대기

- 위임을 마쳤고 메인의 독립 작업이 없으면 `wait_agent`로 결과를 기다린다. 담당 경로 중복 탐색·편집·검증, 짧은 간격 상태 조회, 대기용 문서 갱신과 의미 없는 진행 보고를 하지 않는다.
- `.codex/hooks/delegation-wait.py`는 `SubagentStart`·`SubagentStop`으로 실행 중 작업자를 기록하고, `PreToolUse`에서 메인의 중복 도구 사용을 차단한다. 작업자 본인의 호출과 대기·필수 조율·추가 위임은 허용한다.
- 메인과 작업자는 최초 위임 호출의 실행 주체(`agent_id` 또는 `transcript_path`)로 구분한다. 작업자 종료는 해당 작업자만 해제하며, 기존 작업자 재개 시 제한을 다시 건다. 상태는 세션별 임시 파일과 파일 잠금으로 관리하고 `SessionEnd`에 정리한다.
- 새 사용자 지시는 진행 중 제한보다 우선한다. 자동 작업자 보고·훅 프롬프트는 새 사용자 지시로 취급하지 않는다. 이후 새 위임·작업자 재개 시 대기 제한을 다시 적용한다.
- 훅이 지원하는 도구 호출 경로를 대상으로 한다. 모델 추론 중지·화면의 idle 표시·토큰 절감량은 보장하지 않는다. 새 훅 정의는 Codex 신뢰 검토와 실제 런타임 이벤트 확인이 필요하다.
