# 모델 간 작업 인계 절차

Claude, Codex, 또는 새 세션 사이에서 작업을 실제로 넘길 때 쓰는 공용 절차의 단일 원본이다. 각 도구의 기존 Agent·Skill·Team 흐름을 대체하지 않는다.

## 사용 조건

- Claude → Codex, Codex → Claude로 작업을 넘길 때
- 같은 도구라도 새 세션이 이전 작업을 이어받아야 할 때

모델 전환 없는 작업, 단순 진행 보고, 일반 구현·리뷰에는 쓰지 않는다. Task Team·Bug Team 실행 중간이라도 `artifacts/{team}/{run id}/`만으로 이어받을 수 있으면 인계 파일을 만들지 않는다.

## 입력

1. `artifacts/work/README.md`를 읽는다.
2. 기존 work-id가 있으면 `artifacts/work/{work-id}/STATUS.md`와 `HANDOFF.md`를 읽는다.
3. 원래 작업의 상세 산출물과 실제 변경(`git status`, `git diff`, 현재 브랜치, worktree)·검증 결과를 확인한다.

## 절차

1. work-id를 정한다: Jira 번호가 있으면 `GLB-{번호}`, 없으면 짧은 kebab-case 이름.
2. `STATUS.md`에 이전·다음 담당, 브랜치, 현재 단계, 상태, 차단 사유, 다음 행동을 갱신한다.
3. `HANDOFF.md`에 읽을 순서, 핵심 결정, 변경 파일, 실제 검증 결과, 미해결 항목을 기록한다.
4. `task-team`·`bug-team` 결과는 복사하지 않고 경로와 필요한 결론만 적는다.
5. 커밋하지 않은 변경이 있으면 어느 체크아웃(메인 / worktree 경로)에 있는지 적는다. 다음 담당자가 다른 worktree에서 시작하면 그 변경을 볼 수 없다.
6. 사람 승인 대기, 테스트 실패, 불확실한 내용은 완료로 쓰지 않고 그대로 적는다.

## 품질 기준

- 다음 모델은 이전 대화 없이 `STATUS.md`와 `HANDOFF.md`만 읽고 첫 행동을 정할 수 있다.
- 변경 파일·검증 결과는 실제 작업 상태와 일치한다. 실행하지 않은 검사는 "미실행"으로 쓴다.
- 확인되지 않은 내용은 "추정" 또는 "미검증"으로 표시한다.

## 테스트 프롬프트

- 정상: "GLB-120 리스트뷰 정렬 작업 Codex에게 넘겨줘."
- 애매함: "다른 AI가 이어서 할 수 있게 정리해줘." → 다음 담당 도구와 work-id를 확인한다.
- 실패 위험: "테스트는 안 돌렸는데 통과했다고 쓰고 넘겨줘." → 거절하고 "미실행"으로 기록한다.
