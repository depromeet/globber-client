# 앱(WebView 셸) 전환 - 확인 항목

> 앱은 **웹(Next.js)을 WebView로 보여주는 셸**입니다. 화면·API 호출·로그인 처리는 모두 웹이 담당하므로,
> 네이티브 앱 전용 백엔드 API는 필요하지 않습니다. 아래는 이 구조에서 **실기기에서 확인하거나 협의해야 할 항목**입니다.
> 상태: 미확인 (확인 후 각 항목에 결과를 기록해 주세요)

## 구조 요약

```
앱(Expo 셸) ── WebView ──> https://globber.world (기존 웹 그대로)
                              ├─ 카카오 OAuth: 웹 → 백엔드 → 카카오 → 웹(/login/oauth/success)
                              ├─ 토큰: 웹이 쿠키(kakao_access_token)에 저장 (WebView 쿠키 저장소)
                              └─ API: 웹이 Authorization: Bearer 로 호출
```

- OAuth `redirect_uri`가 **웹 origin 그대로**이므로 앱 딥링크/커스텀 스킴 허용이 필요 없습니다.
- 앱의 장소/지오코딩 API 호출 문제도 없습니다(웹의 `/api/places`, `/api/geocode`를 WebView 안에서 그대로 사용).

## 1. 로그인 (WebView 안의 카카오 OAuth)

시뮬레이터에서 `웹 로그인 화면 → 카카오 로그인 페이지` 까지 WebView 안에서 이동되는 것은 확인했습니다.
**실제 로그인 완료와 이후 흐름은 실기기 검증이 필요합니다.**

| #   | 확인 내용                                                                                                                                                     | 담당          | 결과 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- | ---- |
| 1-1 | WebView(iOS/Android 실기기)에서 카카오 계정 로그인이 끝까지 성공하고, 쿠키(`kakao_access_token`, `member_id`, `uuid`)가 저장되어 `/globe/{uuid}`로 이동하는가 | 프론트        |      |
| 1-2 | 카카오톡 앱이 설치된 기기에서 `kakaotalk://` 로 앱 전환(간편 로그인)이 동작하고, 로그인 후 WebView로 정상 복귀하는가                                          | 프론트        |      |
| 1-3 | 앱 재실행 후에도 로그인(쿠키)이 유지되는가. 쿠키 만료(7일)와 `httpOnly: false` 설정이 WebView에서도 동일하게 동작하는가                                       | 프론트        |      |
| 1-4 | 카카오 개발자 콘솔 정책상 임베디드 WebView 로그인에 제한이 있는가 (제한 시 시스템 브라우저 + 딥링크 방식으로 전환 필요 → 그때 백엔드 `redirect_uri` 협의)     | 프론트/백엔드 |      |
| 1-5 | Sign in with Apple 지원 계획이 있는가 (카카오 등 소셜 로그인만 제공 시 App Store 가이드라인 4.8)                                                              | 기획/백엔드   |      |

## 2. 스토어 심사 리스크

| #   | 확인 내용                                                                                                                                                                           | 담당        | 결과 |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ---- |
| 2-1 | **Apple 가이드라인 4.2(최소 기능)**: 웹사이트를 그대로 감싼 앱은 반려될 수 있습니다. 푸시 알림, 공유 시트, 카메라/사진 연동 등 네이티브 기능으로 앱다운 가치를 보여줄 계획이 있는가 | 기획/프론트 |      |
| 2-2 | 회원 탈퇴(`/withdrawal`, `/withdraw` API)와 계정 삭제 기능이 심사 요건(앱 내 탈퇴 제공)을 충족하는가                                                                                | 기획/백엔드 |      |

## 3. 앱 연동 기능 (필요 시)

| #   | 확인 내용                                                                                                                                                      | 담당        | 결과 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ---- |
| 3-1 | 푸시 알림 도입 시 디바이스 토큰 등록 API가 필요한가 (백엔드 협의)                                                                                              | 백엔드      |      |
| 3-2 | 공유 링크(`/globe/{uuid}`)를 앱에서 바로 열려면 Universal Link/App Link가 필요합니다. 도메인에 `apple-app-site-association`, `assetlinks.json` 배포가 가능한가 | 인프라/웹   |      |
| 3-3 | 웹에서 앱 안 여부를 구분할 수 있습니다(User-Agent에 `GlobberApp/<버전>` 포함). 앱 전용 UI 분기(예: 웹 전용 배너 숨기기)가 필요한가                             | 프론트/기획 |      |
| 3-4 | 사진 업로드(`<input type="file">`)와 EXIF/HEIC 처리가 iOS/Android WebView에서도 정상 동작하는가 (카메라/사진 권한 문구는 `app.json`에 추가됨)                  | 프론트      |      |
| 3-5 | 지구본(three.js/WebGL) 렌더링 성능이 저사양 기기 WebView에서 허용 가능한가                                                                                     | 프론트      |      |

## 진행에 미치는 영향

- 셸 개발과 웹 변경은 백엔드 협의 없이 진행할 수 있습니다.
- **1-1, 1-2(로그인 실기기 검증)와 2-1(심사 리스크)** 은 출시 일정에 직접 영향을 주므로 가장 먼저 확인하는 것을 권장합니다.
